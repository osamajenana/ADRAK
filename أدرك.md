# ADRAK — Implementation Plan

## 1. فكرة المشروع

منصة تعليم تكيفي لمعالجة الفاقد التعليمي، تعمل Offline-first.

النظام يحدد مستوى الطالب الحقيقي عبر اختبار تشخيصي، يحدد المهارات الناقصة، ثم ينشئ له مسار تعلم شخصي ويعدل مستوى الأسئلة حسب أدائه.

## 2. المستخدمون

* Student
* Teacher
* Admin

## 3. الـ MVP

### Student

* تسجيل الدخول.
* إجراء Diagnostic Test.
* عرض Skill Map.
* عرض Recovery Path.
* دراسة Skill.
* حل تمارين.
* تحديث Mastery Score.
* الانتقال للمهارة التالية عند الإتقان.
* حفظ التقدم Offline.
* مزامنة التقدم عند توفر الإنترنت.

### Teacher

* مشاهدة الطلاب.
* مشاهدة مستوى كل طالب.
* مشاهدة المهارات الناقصة.
* مشاهدة الطلاب المتعثرين.
* تقسيم الطلاب تلقائيًا إلى مجموعات حسب المهارة الناقصة.

### Admin

* إدارة الطلاب والمعلمين.
* إدارة المواد والمهارات.
* إدارة الأسئلة.
* Dashboard للفجوات التعليمية والتقدم.

ابدأ فقط بـ:

ولا تضف العربي حاليًا.

## 5. Diagnostic Test

الاختبار لا يكون ثابتًا.

المنطق:

```text
Start with medium skill

Correct
→ test harder skill

Wrong
→ test prerequisite skill

Continue until student level is identified
```

الناتج:

```text
Mastered Skills
Weak Skills
Missing Skills
```

---

## 6. Mastery Engine

لكل طالب ولكل Skill:

```text
student_id
skill_id
mastery_score
attempts
correct_answers
status
```

الحالات:

```text
not_started
learning
mastered
```

مثال:

```text
mastery_score >= 85
→ mastered
```

بعد Mastered:

```text
unlock next skill
```

---

## 7. Recovery Path

بعد Diagnostic Test:

النظام يجلب كل المهارات المطلوبة للوصول للمستوى المستهدف.

يحذف المهارات التي أتقنها الطالب.

ويرتب الباقي حسب Skill Graph.

مثال:

```text
Division
→ Fractions Basics
→ Fractions Operations
→ Decimals
→ Ratios
```

---

## 8. Adaptive Exercises

كل سؤال مربوط بـ:

```text
skill_id
difficulty
question
answers
correct_answer
hint
```

Difficulty:

```text
easy
medium
hard
```

المنطق:

```text
2 correct answers
→ increase difficulty

2 wrong answers
→ decrease difficulty

Repeated failure
→ suggest prerequisite skill
```

---

## 9. Smart Groups

Teacher Dashboard يجمع الطلاب حسب Weak Skill.

مثال:

```text
Division:
- Student A
- Student B
- Student C

Fractions:
- Student D
- Student E
```

ويعرض:

```text
Students needing intervention
```

إذا الطالب فشل أكثر من عدد معين من المحاولات.

---

## 10. Offline First

Frontend يكون PWA.

يخزن محليًا:

```text
student progress
questions
skills
answers
learning path
```

باستخدام:

```text
IndexedDB
```

كل عملية تنشئ Sync Event:

```text
id
device_id
student_id
type
payload
created_at
synced_at
```

عند رجوع الإنترنت:

```text
send unsynced events
↓
server stores them
↓
mark as synced
```

## 17. الهدف النهائي للـ MVP

يجب أن يكون الـ Demo قادرًا على تنفيذ السيناريو التالي:

```text
Student Login
↓
Diagnostic Test
↓
Skill Gaps Detected
↓
Recovery Path Generated
↓
Student Starts Skill
↓
Adaptive Questions
↓
Skill Mastered
↓
Next Skill Unlocked
↓
Teacher Dashboard Updated
↓
Internet Disconnect
↓
Student Continues Offline
↓
Internet Returns
↓
Progress Syncs
```

هذا هو Scope المشروع الأساسي.
